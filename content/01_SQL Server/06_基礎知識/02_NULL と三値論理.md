# NULL と三値論理
キーワード: NULL / ISNULL / IS NULL

> 本ページでは、DB初心者が必ず陥る「NULL」の罠と「三値論理」というDB特有のルールを解き明かし、意図しないバグを防ぎます。

### ０．はじめに

本ページは、WHERE句を以下のように書いたときに、 `NULL` が原因で意図した出力結果を得られなかったことを発端に作成しています。

```sql
SELECT
	user_name
	,age
	,flag
FROM USERS
WHERE
	flag <> '1' 
```

### １．プログラミングの `null` と DB の `NULL` の決定的な違い

#### プログラミングの `null` =「空要素の値」

プログラミングの世界では、 `null` は「何もないこと」を示す一種の特別な「値」として扱われるため、変数に代入したり、比較演算子で等しいかどうかを判定したりすることができます。

#### データベースの `NULL` ＝ 「値ではなく、未知の目印（マーク）」

一方、リレーショナルデータベースの世界において、 `NULL` は<strong>絶対に「値」ではありません。</strong>
値が存在しないフィールドに置かれている、単なる 「目印（マーク）」 に過ぎないのです。
`NULL` は、値ではないという大前提を理解できていないと、 WHERE句 や CASE句 などの処理で恐ろしいバグを引き起こしてしまいます。
データベースの理論において、この `NULL` は主に以下の2つの意味を持ちます。

- <strong>Unknown（未知）：値は存在するはずだが、まだ分からない。</strong>
例： ユーザー登録時に「年齢」の入力をスキップした状態。年齢という概念は存在するが、システム側がそれを把握していない。
- <strong>Inapplicable（適用不能）：そもそも、その項目が存在し得ない。</strong>
例： 現職で働いている社員の「退職日」カラム。まだ退職していないため、概念自体が適用できない。

### ２．データベース特有の「三値論理」

プログラミングの世界の条件式は、True（真）か、False（偽）かの<strong>「二値論理」</strong>で動いています。
しかし、リレーショナルデータベースの世界は、True（真）、False（偽）に加えて、Unknown（不明）という3つ目の状態が存在する<strong>「三値論理」</strong>で動いています。

なぜ Unknown が必要なのか？
前述のとおり、 `NULL` が値ではなく<strong>「未知」</strong>だからです。
例えば、 `NULL` と 20 が等しいかどうかを比較（NULL = 20）したとします。
これを「等しい（True）」とも「等しくない（False）」とも断言できません。
なぜなら、**相手が何か分からないので、判定不能**と解釈します。
したがって、比較演算子のどちらか一方にでも  `NULL`  が含まれていた場合、必ず <strong>Unknown（不明）</strong> になります。

### ３．`NULL` の演算や文字列操作における感染力

`NULL` の特殊な性質は、条件判定だけでなく、計算や文字列操作にも影響を及ぼします。
`NULL` は、他のあらゆる値を巻き込んで**自分自身（NULL）に変えてしまう**という、強い**感染力**を持っています。

- **四則演算での感染**
100 + NULL の結果はどうなるでしょうか？
100に「中身の分からない `NULL` 」を足しても、合計は「分からない `NULL` 」ままです。
したがって、100 + NULL の結果は 100 ではなく `NULL` になります。
- **文字列操作での感染**
苗字と名前を結合してフルネームを作る際などに、片方が `NULL` だと四則演算と同様に `NULL` になってしまいます。

このように、`NULL` を不用意に演算や文字列操作に巻き込むと、データの挙動がおかしくなってしまいます。

### ４．対策

#### 対策①：ISNULL

「ISNULL」を使えば、 `NULL` かどうかを特定することができます。
具体的には、以下のように `WHERE句` で `NULL` を空白に変換して、 `WHERE句` で比較を行います。
※IS と NULLの間はスペースなしです。

```sql
SELECT
	user_name
	,age
	,flag
FROM USERS
WHERE
	ISNULL(flag, '') <> '1'
```

#### 対策②：IS NULL

対策②は `WHERE句` で比較する前に「IS NULL」を用いて変換してしまいます。
具体的には、以下のように `SELECT句` で `NULL` を空白に変換して、その後に比較を行います。
※IS と NULLの間はスペースありです。

```sql
SELECT
	user_name
	,age
	,new_flag
FROM(	
	SELECT
		user_name AS user_name
		,age AS age
		,IIF(flag IS NULL, '', flag) AS new_flag
	FROM USERS
) AS A
WHERE
	new_flag <> '1'
```
